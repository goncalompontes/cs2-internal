# Straight-input air-gain correction — 2026-10-22

The previous native directional plan alternated its near-heading target side on each slice while limiting each emitted yaw step to 45 degrees. With a straight wish and 300 units/second velocity, that produced a 45, 0, 45, 0 degree sequence. Each wish projected more than the 30-unit air cap onto the current velocity, so no acceleration was available. Tests previously required only non-decreasing speed, which admitted zero-gain output.

Native directional plans now select the turn side once per command, then recompute the ideal angle using the current simulated velocity on every slice. The admitted yaw can reach the gain angle instead of reversing early. Each following command re-evaluates heading error; alternation advances only when a near-heading gain choice was consumed, so forced heading corrections do not consume the opposite phase. Physical prefix handling, timestamp-derived dt, non-braking guard, real-camera intent, command-frame encoding and event ownership are retained.

New checks require positive gain in both the pure planner and the actual decoded fixture command. An aligned model run must accelerate on each command and retain a bounded heading sweep; the test prints its measured model result. For the tested state (300 initial speed, 250 wish speed, air acceleration 12, cap 30, friction 1, stamina 0, 16 slices, 1/64 second command), the first command gains 4.151 units/second. Sixty modeled commands produce 490.382 units/second from 300. These are synthetic model results, not a live CS2/server measurement.

The fixture's stronger gain comes from reaching admissible acceleration angles, not changing server physics, writing velocity or generating extra simulation iterations. Non-default live convar discovery remains outside this correction. The earlier Velocity comparison's per-slice side alternation description is superseded by this note; per-slice ideal-angle recomputation remains active.
