# Actual movement capture and prestate correction — 2026-10-22

The user identified the remaining jitter as first-person weapon/viewmodel motion. The desktop capture from the silent-strafe package contains 135 asynchronous samples, 67 with air steering active. Camera hook/restoration verified in all 135, opposing wish stayed zero, autostop was false throughout, no CRC failures were reported, and the steering window began at zero in all samples. These observations do not support counter-braking, autostop or a missed camera hook as the main issue in that run. They do not directly measure viewmodel bone/pose motion.

Among active samples, current-source minus last-processed command was one in 19 samples and zero in 48. CRC writes advanced 2742 while source command advanced 916: approximately three build callbacks per command. Our adapter reset its state cache on every apply, so it could recalculate a command against the simulated velocity and movement-service impulses from a later callback. The capture is asynchronous and not a complete command trace, but the code admits this phase mismatch, and a deterministic regression now reproduces it.

The adapter now freezes the first valid pre-prediction movement state for each command/pawn and reuses it for duplicate callbacks. The next command refreshes it. A first encounter whose last-processed command is already equal/newer is rejected, labeled "command already simulated (no prestate)" and counted as a miss; it does not invent a baseline. Rebuild tests modify velocity, service impulses and processed counter after the first apply, then require byte-identical steering from the cached prestate.

A read-only physics adapter obtains VEngineCvar007 from tier0, walks the bounded reference container, checks exact names, consistent float representations, finite value ranges and bool validity, and reads sv_airaccelerate, sv_air_max_wishspeed, sv_staminarecoveryrate and sv_quantize_movement_input. Valid values drive the model. Invalid/unavailable bindings retain documented fallback settings and report movement_physics_valid=false. No flags or convar values are changed. Tests cover live-value updates, invalid values/types and cyclic/out-of-range links. This binding still requires verification in the user's process; a valid fake registry fixture is not live verification.

The capture now reports physics values, prestate reuse/miss counters and the prior camera/gain fields. A low-rate [movement-state] line is written to the existing local payload log once per second while strafe is enabled so session-0 pipe access is not needed to inspect basic runtime evidence.

No cosmetic viewmodel pose write or bob-removal switch was added. The exact viewmodel transform/animation cause has not been measured. This build fixes a demonstrated movement-state handling defect and removes the unverified model-physics default assumption where live binding succeeds; it does not establish that the reported viewmodel jitter or weak live gain is resolved. A new desktop capture and user observation are required.
