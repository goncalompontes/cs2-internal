# Native live damage, held-key shots and frame latency fixes

The prior build did not install a live world-damage callback. Empty world geometry was evaluated as an unoccluded shot, with world_known=false. The native keybind now binds the installed client's filter initializer, bullet trace initializer and bullet damage routine. Functions must match unique executable patterns. The trace initializer is anchored by its write to trace.start (+0x1cf8), because the shorter reference pattern had two matches. Installed-PE candidates were filter 0x352920, trace initializer 0x8830e0 and bullet simulation 0x885710. These RVAs are evidence only; runtime code scans rather than embedding them.

Trace data uses bounded inline storage (128 contacts, 8 hit records). Four penetration steps, the supplied weapon damage/penetration/range modifier, local-team context and a filter excluding the local pawn are passed to the engine. Failed exits, misses and other actors do not become target damage. Malformed counts, contact indices, pointers and NaNs produce unknown/zero damage. Live keybind acceptance requires known world damage and a plausible live weapon profile. The analytic material attenuation model remains available to explicit synthetic inputs; it is not used as live autowall.

Fields are looked up through SchemaSystem_001 and client.dll's type scope, with bounded field-array reads and caching. Live values override generated/literal player and weapon offsets, including the armor field which previously produced impossible values in the user's log. Full weapon parameter reads are validated together. Helmet state is taken from the item services when available. A current recoil call site is bound only when its services displacement agrees with m_pAimPunchServices in the runtime schema; compensation is sampled at command time. Its game behavior still requires live confirmation.

The command writer stamps view-angle message presence and attack1_start_history_index for every aimed attack, including manual fire. It supports 64 history entries, refuses synthetic attack without a stamped entry, reads pitch/yaw as a coherent publication, and preserves non-attack button bits. Synthetic held state no longer advertises a new press every tick. Repeated hooks for the same command preserve its original edge. Key state is checked on the command thread and completed aim expires after 150 ms. Worker results from snapshots older than 100 ms are discarded before publication.

The render sink now only posts the newest snapshot to a worker; intermediate snapshots are replaced rather than queued. A blocking damage callback therefore cannot block Present. Camera projection and ESP draw commands are rebuilt every Present, player state is sampled up to 125 Hz, and debug HUD formatting runs at 4 Hz. Entity pages are read in blocks and the render snapshot classifies controller identities by cached designer names rather than probing every entity object. The full harness snapshot still checks rules proxies. Safe OS memory reads are retained; an attempted direct-copy optimization failed an invalid-address test and was removed.

Validation: 17 host tests and 9 payload tests pass. New tests cover 100 sustained commands (including duplicate hook visits), history indices, attack edges, missing/full histories, expiry, recoil adjustment, trace identity/material failure handling, fast/full snapshot equivalence, invalid pointers and a deliberately blocked worker. The rebuilt payload renders in the hidden WARP integration host. These tests do not execute the client's bullet functions or prove server damage, shot registration, live recoil scale, command-seeded spread or current lag compensation. The next in-game run must verify [ballistics] engine bullet trace bound, [schema] live client player fields resolved, and the actual results.
