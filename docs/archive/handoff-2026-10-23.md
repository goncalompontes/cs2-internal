## 2. The instruments (use these, do not re-derive)

* **`debug {"on": true}`** — on-screen column: `screen`, capabilities, `rage on/active/target/hitbox/solve <refusal>`, fire mode/refusal/presses/shots, the world enumeration (`solids`, `mesh clusters`, `kept`), the shape histogram, the solve (`occluders`, query state, `solves`, `project/solve µs`), **`last solve value/hitchance/wall/cells`**, `aim yaw/pitch`, the fire facts (`clip`, `reload`, `deploy`, `ready`), the weapon with its **`type`**, and the weapon entity/VData pointers. It answers the question in the first look.
* **`trace_probe`** (`cs2_trace_probe`, or `python artifacts/trace_probe.py yaw=… pitch=…`) — the engine's own `TraceLineIntervals` answer next to ours, plus `world.{kept, record_handles}`.
  * `enum: "box"` — the single eye→far-end AABB instead of the per-target pyramid.
  * `at: [x,y,z]` — cached solids containing a point (the cache-vs-selection discriminator).
  * `box_min`/`box_max` — an explicit enumeration volume (**both** the engine query and the world selection; the first version only changed the engine query and lied).
  * `abi: "swapped"` / `"static_filter"` — deliberately wrong, to prove the probe can fail.
* **`python artifacts/check_aim.py`** — reads the ragebot's `solve_yaw/pitch` and probes **that** ray. The one-command test for "the solve says clear, the engine says wall".
* **`python artifacts/repro_occlusion.py <name>`** — freezes the scene (local eye/angles, every player's origin, the probe's answer) to `artifacts/repro-occlusion-<name>.json`. `artifacts/` is **gitignored**: copies do not travel with the repo.

## 3. What the probes established (so it is not re-derived)

1. **The world's meshes are parsed and found**: 10226 cached solids = 10143 hulls + 83 mesh clusters from the body's 6 meshes, and our mesh crossings land on the engine's own records (e.g. `196.216 / 672.148 / 1476.142 / 2170.481 / 2195.578` on one ray).
2. **A mesh cluster must yield every crossing**, not the nearest — that was the last "shoot through a wall" cause (fix `86275be`).
3. **The engine's interval flag byte is inverted relative to our reading**: our hull `2729.1 → 2749.6` matches engine records `2729.1` **(lve)** and `2749.6` **(ent)**. So our entry coincides with the engine's *leave*. `pair_trace_spans`/`diff_trace` therefore mis-pair and the verdicts (`both`/`engine_only`) are unreliable; **compare distances, not verdicts**, until the record layout is pinned.
4. **`at` works**: a control query at 2740 units on that ray found our hull (`x 89..105, y 2017..2037`), while the point inside the missing span returned only mesh AABBs — that is how the multi-crossing loss was found.
5. **The envelope**: `world kept` in the rage path (hundreds) vs `occluders` (a handful) is the tag/projection filter; it is **correct** now (entity tags), and a lower `occluders` count is expected because the projection is per target.

## 5. The live loop, exactly

```powershell
# 1. build (the MCP tools work again; the quoting fix is in)
python -m mesonbuild.mesonmain compile -C build-payload   # or cs2_build target=payload

# 2. restart the game with the new payload (NEVER inject twice into one process)
python artifacts\game_cycle.py          # Stop-Process cs2 -> CS2Launch task -> inject
#    then WAIT: polling `python artifacts\live.py ping` until "state_ready": true
#    (do not `exec` before that: see §4.2)

# 3. drive it
python artifacts\ensure_live.py de_dust2
python artifacts\live.py rage <json-file>      # {"on":true,"fire":true,"force":true}
python artifacts\live.py debug on=true
python artifacts\live.py debug                 # read the column's text
python artifacts\live.py trace_probe <json>    # yaw/pitch/at/box_min/box_max/enum/abi
python artifacts\check_aim.py                  # the solve's ray vs the engine
```

**Quirks that cost time this session:**

* The payload serves **one client at a time**. The `cs2` MCP server caches its
  connection, so `python artifacts/live.py` is refused while the MCP is live.
  Either use the MCP tools, or stop the MCP server process that owns the
  connection (`Get-NetTCPConnection -RemotePort <port from control.json>`), then
  the scripts work and the MCP reconnects on its next call.
* `setang` is **`setang <pitch> <yaw>`**, and both it and `setpos` need
  `sv_cheats 1` **in the same console line** to take effect in one go.
* `artifacts/*` is gitignored — the probe clients, the repro dumps and the
  commit-message files live there and are **not** committed.
* A restart resets the debug column unless the new build is in (it now follows
  the menu's `show_hud`); `rage`/`fire`/`force` are likewise RAM-only, and the
  menu's block re-applies its own values.
